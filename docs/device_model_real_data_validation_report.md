# 设备模型 real 数据验证报告

## 1. 报告结论

本次使用 `model_base_device_day_line_or_load_like_real.csv` 对项目中已保存的六个设备状态模型进行了独立推理和一致性验证。

结论分为三层：

1. **工程兼容性通过**：real 数据能够完成读取、特征构造、预处理和六个模型推理，没有缺少模型必需字段。
2. **代理风险一致性有限**：DAMD-Net 在 Macro-F1、QWK 和风险等级综合识别上最好，但整体结果明显低于原 enriched quick 内部测试。
3. **暂时不能宣称真实故障预测准确率**：该 CSV 没有未来故障、跳闸或真实状态标签，而且设备与日期面板和 enriched 源数据完全重叠。本报告中的指标是“真实画像数据对既有弱监督风险规则的一致性”，不是实际故障预测效果。

综合判断：当前模型和验证链路可以继续用于研究实验与影子测试，但不建议直接作为生产告警或自动调电依据。下一步应使用真实 D+1、D+7 或 D+30 故障结果标签重新训练和验证。

## 3. 验证设计

### 3.1 设备隔离

保存的训练记录采用按 `unified_device_id` 分组切分：

| 分区 | 设备数 |
| --- | ---: |
| 训练设备 | 4,296 |
| 测试设备 | 1,433 |

本次主验证只选择保存的 1,433 台测试设备，共 128,970 条设备日记录。验证设备与该次模型训练设备的 ID 重叠数为 0。

这可以避免同一台设备同时出现在该次训练和验证分区，但不能证明时间外推能力，因为 real 表与 enriched 源表的设备、日期及设备-日期键重叠率均为 100%。

### 3.2 标签口径

real 数据中没有可直接作为真实结果的 `target`、`fault_label` 或 `state_label` 字段。因此验证脚本使用现有 enriched 弱监督规则生成四级代理状态：

| 标签 | 含义 |
| ---: | --- |
| 0 | 正常 |
| 1 | 关注 |
| 2 | 异常 |
| 3 | 高风险 |

代理规则综合历史缺陷、历史跳闸、缺陷等级、检修状态、家族设备历史、运行偏离、设备年龄和数据覆盖率。它适合检验模型是否保留既有风险逻辑，不等价于真实故障标签。

全量数据中有 64,440 行历史画像不完整，占 12.50%，这些行不参与指标计算。测试设备范围内：

| 项目 | 行数 |
| --- | ---: |
| 模型推理记录 | 128,970 |
| 可生成代理标签的评分记录 | 115,560 |
| 因画像不完整排除 | 13,410 |

115,560 条评分记录的代理标签以正常类为主，单独预测全部为正常即可获得 0.7841 的 Accuracy。因此本报告主要观察 Macro-F1、Balanced Accuracy、QWK 和风险等级召回，不单独依据 Accuracy 选模型。

### 3.3 指标定义

| 指标 | 用途 |
| --- | --- |
| Accuracy | 总体分类正确率，受正常类占比影响较大 |
| Balanced Accuracy | 四个类别召回率的平均值 |
| Macro-F1 | 四个类别 F1 的等权平均，关注少数风险类 |
| QWK | 二次加权 Kappa，衡量四级有序状态的一致性 |
| 风险精确率 | 预测等级大于等于 2 的样本中，代理等级大于等于 2 的比例 |
| 风险召回率 | 代理等级大于等于 2 的样本中，被模型识别出的比例 |

## 4. 模型效果

### 4.1 六模型对比

以下所有结果均基于代理标签：

| 模型 | Accuracy | Balanced Acc. | Macro-F1 | QWK | 风险精确率 | 风险召回率 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| DAMD-Net | 0.7606 | 0.3857 | **0.3812** | **0.5801** | 0.9931 | 0.3033 |
| PyTorch MLP | 0.7114 | 0.4073 | 0.3664 | 0.5116 | 0.9928 | 0.1867 |
| 逻辑回归 | 0.6722 | **0.4182** | 0.2841 | 0.3631 | 0.1868 | **0.8741** |
| 随机森林 | **0.7865** | 0.2742 | 0.2663 | 0.3421 | 1.0000 | 0.1817 |
| 极端随机树 | 0.7860 | 0.2715 | 0.2620 | 0.3257 | 1.0000 | 0.1651 |
| 直方图梯度提升 | 0.7848 | 0.2547 | 0.2313 | 0.3023 | 1.0000 | 0.1246 |
| 全部预测为正常 | 0.7841 | 0.2500 | 0.2198 | 0.0000 | 0.0000 | 0.0000 |

结果解释：

- **DAMD-Net 是当前最佳综合候选**。它的 Macro-F1 和 QWK 最高，说明对少数风险类和等级顺序的保持优于其他模型。
- **DAMD-Net 偏保守**。风险精确率为 0.9931，但风险召回率只有 0.3033，即发出的高等级风险信号较可信，但漏掉了约 69.7% 的代理风险记录。
- **MLP 次于 DAMD-Net**。Balanced Accuracy 较高，但风险召回和 Macro-F1 均低于 DAMD-Net。
- **逻辑回归偏激进**。风险召回率达到 0.8741，但风险精确率只有 0.1868，会产生大量代理误报。
- **三个树模型的 Accuracy 不能作为优势**。它们接近“全部预测为正常”的 0.7841 基线，Macro-F1 和风险召回较低，存在明显多数类塌缩。

### 4.2 DAMD-Net 混淆矩阵

| 代理标签 \ 预测标签 | 正常 | 关注 | 异常 | 高风险 |
| --- | ---: | ---: | ---: | ---: |
| 正常 | 77,280 | 13,336 | 0 | 0 |
| 关注 | 8,476 | 9,823 | 14 | 0 |
| 异常 | 288 | 4,083 | 794 | 0 |
| 高风险 | 0 | 249 | 1,217 | 0 |

DAMD-Net 可以将一部分高风险记录识别为“异常”，因此在合并风险口径 `label >= 2` 下具有较高精确率。但当前模型没有输出最高风险第 3 级，说明四级决策边界仍需重新校准，不能把 0.9931 的合并风险精确率解释为“高风险等级识别率 99.31%”。

### 4.3 设备差异性

DAMD-Net 的四个判别器会为每台设备产生不同门控权重。1,433 台验证设备的平均权重为：

| 判别器 | 平均权重 | 成为设备主导判别器的数量 |
| --- | ---: | ---: |
| 运行波动判别器 | 0.3390 | 552 |
| 历史事件判别器 | 0.1125 | 41 |
| 检修恢复判别器 | 0.2390 | 248 |
| 家族画像判别器 | 0.3096 | 592 |

主导判别器并不集中在单一分支，说明模型确实为不同设备形成了差异化组合。真实画像进入后，家族画像和运行波动分支使用最多；历史事件分支平均权重较低，这与历史字段缺失和编码漂移有关。

## 5. 数据漂移检查

### 5.1 字段兼容

保存模型要求 76 个数值特征和 11 个类别特征。real 数据经过同一特征工程后，没有缺失模型字段，结构兼容检查通过。

结构兼容不代表数据语义一致。类别未见率显示，多个编码字段在训练时只见过少量取值，而 real 数据出现了大量新编码：

| 类别特征 | 未见率 | 验证未见行数 | 训练类别数 | 验证类别数 |
| --- | ---: | ---: | ---: | ---: |
| `manufacturer_code` | 87.16% | 112,410 | 5 | 78 |
| `device_type_code` | 82.27% | 106,110 | 9 | 13 |
| `family_history_defect_reason_code` | 30.49% | 39,328 | 11 | 17 |
| `family_history_defect_type_code` | 18.24% | 23,526 | 9 | 14 |
| `history_defect_reason_code` | 2.16% | 2,790 | 11 | 12 |
| `history_defect_type_code` | 2.03% | 2,613 | 9 | 12 |

当前 One-Hot 编码器对未见类别采用 `handle_unknown="ignore"`，这些取值会被编码为该字段全零。模型虽然不会报错，但会损失真实设备类型和厂家差异信息。

### 5.2 数值分布漂移

76 个数值特征中：

- 27 个特征 PSI 大于等于 0.25，属于明显漂移；
- 28 个特征达到中度或明显漂移；
- 家族历史事件、设备年龄、电压等级和时间索引是主要漂移来源。

部分高漂移特征如下：

| 特征 | PSI | 训练中位数 | 验证中位数 |
| --- | ---: | ---: | ---: |
| `family_history_trip_level_code` | 13.8684 | 4.0000 | 0.0000 |
| `family_event_count_per_device` | 9.0200 | 0.8667 | 0.0493 |
| `family_history_defect_count` | 6.7764 | 20.0000 | 2.0000 |
| `family_history_trip_count` | 6.6660 | 7.0000 | 0.0000 |
| `day_index` | 3.0602 | 2.0000 | 44.5000 |
| `device_age_days` | 2.8400 | 848 | 5,524 |
| `voltage_level_kv` | 2.3276 | 110 | 10 |

`day_index` 漂移的一部分来自 quick 模型只使用前 30,000 行训练，而验证覆盖完整 90 天；其他台账和家族字段则反映 enriched 画像与 real 画像之间的明显语义差异。

## 7. 后续改进

建议按以下顺序推进：

1. 建立统一的设备类型、厂家、缺陷类型和原因码映射，训练与推理共用同一份字典，并为未知值保留显式 `UNK` 类别。
2. 用 real 数据重新训练，不继续让模型主要学习 enriched 随机画像的取值分布。
3. 构造真实时间后验标签，例如设备日 D 的特征对应 D+1、D+7 或 D+30 内是否发生缺陷、跳闸或高等级事件。
4. 使用按时间切分加按设备分组的验证方案，最后一段时间只做测试，禁止未来信息进入滚动特征。
5. 对 DAMD-Net 增加等级校准或有序分类损失，解决不输出第 3 级的问题。
6. 根据业务偏好选择风险阈值：若优先减少漏报，应提高召回；若优先减少误报，可保持 DAMD-Net 当前较保守的阈值。

当数据提供真实四级标签列时，验证脚本可直接改为真实监督评估：

```bash
python scripts/validate_external_device_data.py \
  --csv data/model_base_device_day_line_or_load_like_real.csv \
  --target-col actual_state_label \
  --device-partition test \
  --torch-device cuda \
  --gpu-id 0
```
