# Enriched 数据建模分析与改进说明

## 1. 数据结论

本次接入两张 enriched 日表：

| 数据表 | 有效行数 | 对象数 | 日期数 | 字段数 |
| --- | ---: | ---: | ---: | ---: |
| 设备日表 | 515,610 | 5,729 台设备 | 90 天 | 57 |
| 站点日表 | 6,930 | 77 个站点 | 90 天 | 27 |

日期范围为 2026-02-01 至 2026-05-06。设备日表原文件末尾有一行全空记录，读取时会自动删除。

设备表新增了设备类型、电压等级、运行状态、厂家、设备年龄、历史缺陷、历史跳闸、历史检修、缺陷与检修关系、家族设备统计等字段。站点表补齐了历史事件、站点类型、电压等级、主变数量和容量、雷害风险、冰区等级等字段。

## 2. 数据质量边界

新增字段对搭建建模流程很有帮助，但目前仍不是未来故障预测所需的真实时序标签：

1. 每台设备正好有 90 行，新增历史和台账字段在同一设备的 90 天内全部不变。
2. 每个站点正好有 90 行，历史事件和站点属性同样全部不变。
3. `operation_status_code` 在 515,610 条有效设备记录中全部为 1，没有区分能力。
4. 厂家、设备年龄和部分历史事件字段按规则随机生成，适合验证代码，不适合形成业务结论。
5. 缺陷与检修、跳闸与检修的逻辑关系内部一致，但缺少真实事件日期，无法构造 D+1 至 D+7 的未来事件标签。

因此，当前任务定义为“弱监督状态评估”：用业务规则合成四级风险标签，再比较不同模型对这套规则的泛化能力。报告中的 Accuracy、Macro-F1 等指标不能解释为真实故障预测准确率。

## 3. 特征工程改进

### 3.1 设备特征

保留原有量测、物理关系、滚动统计和同站同类偏离特征，并新增：

- 未处理缺陷数和未处理跳闸数。
- 缺陷检修完成率和跳闸检修完成率。
- 历史事件总数及其对数变换。
- 缺陷数量乘缺陷等级、跳闸数量乘跳闸等级形成的风险负担。
- 家族设备平均事件数。
- 设备年龄年数。

设备类型、厂家、事件类型和事件原因编码改为类别特征，经缺失值处理和 One-Hot 编码后进入模型，不再把编码数字错误地当作连续大小关系。

### 3.2 站点特征

新增：

- 历史缺陷与跳闸总数。
- 未处理事件代理数。
- 历史检修覆盖率代理值。
- 单台主变历史事件数。
- 雷害与冰区综合环境风险等级。
- 当前有功与主变容量的负载代理比值。

## 4. 弱监督标签

### 4.1 设备风险分

设备风险分由以下成分加权：

| 成分 | 权重 |
| --- | ---: |
| 未检修缺陷和跳闸状态 | 28% |
| 历史事件最高等级 | 18% |
| 设备历史事件数量 | 12% |
| 家族设备历史风险 | 12% |
| 当前量测偏离和短期变化 | 20% |
| 设备年龄 | 5% |
| 量测缺失风险 | 5% |

### 4.2 站点风险分

站点风险分由历史事件数量 30%、未处理事件 20%、环境风险 15%、当前运行状态 30% 和数据覆盖风险 5% 组成。

两个任务都将风险分按分位数转换为四级标签：正常 80%、关注 15%、异常 4%、高风险 1%。这保持了风险筛查任务的长尾特点。

## 5. 评估方法改进

旧版采用行级随机切分。同一设备或站点的不同日期可能同时进入训练集和测试集，静态字段会造成明显的数据泄漏。

新版默认使用分组切分：

- 设备模型按 `unified_device_id` 切分。
- 站点模型按 `station_id` 切分。
- 同一对象只会出现在训练集或测试集的一侧。

命令行仍支持 `temporal` 和 `random`。接入真实日级未来标签后，应优先使用时间切分或滚动回测；当前 enriched 数据的历史字段不随日期变化，单独时间切分仍会看到同一对象，因此不如分组切分严格。

## 6. Quick 实验结果

运行命令：

```bash
python scripts/run_baseline_pipeline.py \
  --quick \
  --label-mode enriched_weak \
  --split-strategy group \
  --torch-device auto
```

设备模型测试集包含 1,433 台未参与训练的设备：

| 模型 | Accuracy | Macro-F1 | QWK | 高风险召回 |
| --- | ---: | ---: | ---: | ---: |
| PyTorch MLP | 0.9460 | 0.8632 | 0.9215 | 0.8710 |
| 设备个性化多判别器 | 0.9428 | 0.8142 | 0.9151 | 0.8817 |
| HistGradientBoosting | 0.9522 | 0.7982 | 0.9157 | 0.7661 |
| Random Forest | 0.9388 | 0.7951 | 0.9096 | 0.8038 |
| Extra Trees | 0.9363 | 0.7767 | 0.9000 | 0.7957 |
| Logistic Regression | 0.9251 | 0.6381 | 0.8772 | 0.5430 |

站点模型测试集包含 20 个未参与训练的站点：

| 模型 | Accuracy | Macro-F1 | QWK | 高风险召回 |
| --- | ---: | ---: | ---: | ---: |
| PyTorch MLP | 0.8662 | 0.5486 | 0.8039 | 0.7429 |
| HistGradientBoosting | 0.8547 | 0.4959 | 0.7379 | 0.4857 |
| Extra Trees | 0.8614 | 0.4898 | 0.7751 | 0.6571 |
| Random Forest | 0.8547 | 0.4477 | 0.7603 | 0.4286 |
| Logistic Regression | 0.8056 | 0.3260 | 0.4642 | 0.0000 |

站点样本只有 77 个独立对象，测试集仅 20 个站点，结果波动会比较大。后续不能只增加站点日行数，还需要增加独立站点数量和真实事件样本。

### 6.1 设备个性化多判别器

新增模型使用运行波动、历史事件、检修恢复和设备画像四个判别器，再由门控网络为每台设备生成个性化融合权重。Quick 实验为全部 5,729 台设备生成了专家画像，四类判别器均有对应的主导设备，高风险召回达到 0.8817。

该模型的重点是表达设备间差异和提供单设备风险解释。完整结构、设备画像字段和推荐项目表述见 [device_personalized_multi_discriminator.md](device_personalized_multi_discriminator.md)。

## 7. 经济调电改进

调电风险不再只依赖当日量测异常，还加入：

- 历史缺陷和跳闸风险。
- 未处理事件代理风险。
- 检修可用系数。
- 高风险状态降额。

当前优化目标仍为代理经济目标：

```text
最大化：供电收益代理 - 运行风险惩罚
```

由于还没有节点电价、发电成本、网损、潮流约束、线路热稳限额和真实停电损失，当前结果只能作为调电优先级原型，不能直接下发生产调度指令。

## 8. 下一阶段真实预测标签

建议把缺陷、跳闸和检修事件表按设备 ID、站点 ID 与日期对齐，构造：

```text
特征截止日：D 日 23:59:59
目标窗口：D+1 至 D+7
设备目标：窗口内是否发生缺陷或跳闸、最高事件等级
站点目标：窗口内高风险设备比例、事件数量和最高事件等级
```

历史统计必须按 D 日截断后累计，不能把 D 日之后的信息写入 D 日特征。完成这一层后，当前 `--target-col`、时间切分、多模型和 GPU 训练框架可以继续复用。
