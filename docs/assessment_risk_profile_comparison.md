# 分级评估结果、风险分与画像的区别

| 项目 | 分级评估结果 | 风险分/高风险概率 | 画像 |
| --- | --- | --- | --- |
| 回答的问题 | 当天属于哪一个状态等级 | 当天风险程度有多高 | 一段时间内的稳定特征是什么 |
| 时间范围 | 单日 | 单日 | 显式的开始日期到结束日期 |
| 输出形式 | `state_level=0～3` 和 `state_name` | 站点 `risk_score=0～100`；设备/站点均有 `high_risk_probability=0～1` | 样本数、平均风险、平均置信度和平均权重 |
| 是否为独立模型 | 是，由分类头输出 | 站点风险分由 HSF-Net 独立风险头输出；高风险概率由分类概率合并 | 否，对多个单日结果做区间聚合 |
| 设备是否支持 | 支持 | 支持 `high_risk_probability`，不单独输出 0～100 `risk_score` | 支持 |
| 站点是否支持 | 支持 | 同时支持 `risk_score` 和 `high_risk_probability` | 支持 |
| 主要接口 | `/api/device/assessment`、`/api/station/assessment` | `/api/station/assessment`、`/api/risk/overview` | `/api/device/profile`、`/api/station/profile` |

## 字段关系

| 字段 | 定义 | 注意事项 |
| --- | --- | --- |
| `state_level` | 四级分类头的最大概率类别 | 是离散等级，不是连续分数 |
| `confidence` | 分类头四类概率中的最大值 | 表示模型对当前分类的把握程度 |
| `high_risk_probability` | `abnormal` 与 `high_risk` 两类概率之和 | 可用于排序，不应解释为经过校准的真实事故发生率 |
| `risk_score` | HSF-Net 风险头输出的 0～100 连续分 | 只用于站点，与 `state_level` 来自不同输出头 |
| `dominant_discriminator` | 设备模型四判别器中权重最高者 | 只表示模型当次更依赖的特征类型 |
| `dominant_view` | 站点模型三视图中权重最高者 | 不等于可审计的故障原因 |

## 风险来源能否定位

当前接口可返回判别器或视图权重，因此可以说明模型本次更依赖“运行、历史、检修、设备画像”中的哪一类信息。这种权重是模型内部注意程度，不是因果证据，不能直接返回“某条缺陷就是当前风险原因”。

如后续需要可追溯风险来源，应在模型权重之外增加规则证据层，返回与评估日期相关的缺陷编号、跳闸编号、检修单号和超限测点。该能力需要明确的事件主键与业务规则，当前 API 不伪造这类因果说明。
